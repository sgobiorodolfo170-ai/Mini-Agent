## 1. 进程与窗口模型

### 1.1 进程模型

- **Main（Node.js 主进程）**：系统能力与数据访问的唯一入口——模型网关、RAG、Agent 运行时、SQLite、safeStorage、托盘/快捷键/划词/截屏。
- **Renderer（Vue 3 渲染进程）**：纯 UI。安全基线：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`，只通过 preload 暴露的 `window.api` 与主进程通信。
- **Preload**：按窗口注入最小 API 面（主窗口 / 快速窗 / 悬浮球各自一套），全部走 `ipcRenderer.invoke` / `ipcRenderer.on`。

### 1.2 窗口清单

| 窗口 | 形态 | 生命周期 |
|---|---|---|
| 主窗口 | 三栏常规窗 | 关闭 → 隐藏到托盘，托盘「退出」才真退出 |
| 快速输入窗 | frameless + alwaysOnTop + skipTaskbar，屏幕中上 | 应用启动即创建并隐藏（保证 ≤300ms 唤起），Esc 隐藏 |
| 悬浮球 | frameless + transparent + alwaysOnTop 小窗 | M5 实现；支持隐藏 |
| 框选截屏层 | frameless + 全屏 + transparent 覆盖层 | 按需创建，完成后销毁 |

Vite 多入口：`src/entries/{main-window, quick-panel, floating-ball, screen-capture}`。

## 2. 关键流程设计

### 2.1 对话流式链路

```
Renderer: chat.send(sessionId, input)
  → Main gateway: 组装 messages / 工具 / 检索上下文
  → 选 Key（见 2.2）→ fetch(SSE, undici, AbortController)
  → 每收到 delta: webContents.send(`chat:delta:${msgId}`, chunk)
  → 结束/出错: chat:done / chat:error（含 Key 切换说明）
Renderer: 逐段拼接渲染；停止 = invoke chat.stop → AbortController.abort()
```

- 取消、重试、编辑重发都在主进程重建请求；
- 消息在 done / error 时各落库一次，streaming 期间渲染层本地暂存。

### 2.2 Key 调度（网关核心）

- 状态机：`unknown → ok / invalid(401/403) / cooldown(429，恢复时间取 Retry-After 或 60s×n)`；任何成功请求 → ok。
- **故障转移（默认）**：按序取 ok 状态的 Key；请求失败（网络错误 / 5xx / 429 / 401 / 403）标记状态后自动换下一把，重试上限可配（默认 3 把）。
- **轮询**：ok 状态 Key 列表轮转使用。
- 探测器：每把 Key 周期性发最小化 `/chat/completions`（`max_tokens=1`），间隔可配（默认 30 分钟），支持手动立即探测 / 全量探测；结果写 `key_events`。

### 2.3 划词（M2）

- 触发：全局快捷键（默认 `Alt+Q`）→ PowerShell SendKeys 模拟 Ctrl+C → 读剪贴板（diff 检测选中文本）→ 复用快速输入窗以「划词模式」展示（翻译/总结/解释/自定义模板）。
- 模板：翻译 / 总结 / 解释 / 自定义 Prompt，结果可复制、可转入主窗口继续对话。
- 已知边界：管理员权限/部分全屏窗口可能取不到剪贴板变化，此时提示改用「截屏问 AI」；悬浮小按钮（需鼠标钩子）列为增强项，不进 v1。

### 2.4 截屏问 AI（M2）

- globalShortcut → 全屏透明覆盖窗 → 鼠标框选（v1 先取光标所在屏）→ `desktopCapturer` 抓该屏 → 按选区裁剪 → dataURL → 组装 vision 消息（仅可选标记「支持视觉」的模型）→ 结果进主窗口新会话。

### 2.5 Agent 循环（M4）

```
loop (maxSteps 默认 15):
  请求模型（带 tools 定义 + 历史消息）
  ├─ finish_reason=stop → 结束，落 agent_runs
  └─ tool_calls → 逐个工具:
       权限判定（只读放行 / 副作用确认 / 破坏性确认）
       确认交互：主窗口确认卡片（展示完整命令 / 写入路径与内容摘要）
         可勾选「本会话同类操作不再确认」（仅副作用级）
       执行 → 结果作为 tool 消息回传
  用户「停止」→ 中断循环，落日志
```

- 工具实现全部在主进程；
- 文件类工具以授权目录白名单校验（realpath 解析后前缀匹配），默认不授权任何目录；
- 命令执行统一 PowerShell，参数转义，加超时（默认 60s）与输出截断；
- 全部调用落 `agent_tool_calls` 日志。

### 2.6 RAG（M3）

- 导入：pdf / docx / md / txt → 抽取文本 → 切块（按标题结构 + 长度上限 + 重叠，参数可配）→ `/embeddings` 批量向量化 → 写 `kb_chunks` + `kb_embeddings` 主表（Float32 BLOB）；
- 检索：查询向量化 → Top-K（默认 5）→ 相似度阈值过滤 → 组装带编号来源的引用上下文；
- 引用：回答解析 `[n]` 标记渲染引用卡片，点击展示原文片段与所属文档。

## 3. 数据模型（SQLite v1）

约定：所有业务表含 `id TEXT PK (uuid)`、`created_at INTEGER`、`updated_at INTEGER`、`deleted_at INTEGER NULL`（软删，预留同步）。

| 表 | 关键字段 |
|---|---|
| settings | key TEXT PK, value JSON |
| providers | name, base_url, rotation_strategy, probe_interval_min, enabled |
| api_keys | provider_id, label, secret_enc BLOB(safeStorage 密文), status, cooldown_until, last_used_at |
| key_events | api_key_id, kind(probe/request), result(ok/invalid/rate_limited/error), detail, at |
| conversations | title, pinned, provider_id, model, system_prompt, context_policy JSON |
| messages | conversation_id, role, content, tool_calls JSON, attachments JSON, tokens, status(streaming/done/error/stopped), seq |
| kb_documents | kb_id, path, title, mime, size, hash, chunk_count, status |
| kb_chunks | document_id, seq, heading_path, text, token_count |
| kb_embeddings | 主表存储：chunk_id, kb_id, dim, embedding BLOB；检索用 JS 余弦 Top-K（个人规模） |
| agent_runs | conversation_id, goal, status, max_steps, started_at, ended_at |
| agent_tool_calls | run_id, step, tool, args JSON, risk_level, confirmed_by(user/auto/session), result JSON, duration_ms |

向量维度随 Embedding 模型（常见 1024 / 1536 / 3072）；更换 Embedding 模型需重建索引。

## 4. IPC 接口清单（命名空间）

| 命名空间 | 主要通道 | 说明 |
|---|---|---|
| settings.* | get / set | 通用配置 |
| gateway.provider.* | list / save / delete / probeKey / probeAll | 供应商与 Key 管理 |
| gateway.model.* | list | 可用模型（含 vision 标记） |
| chat.* | send / stop / regenerate / export + delta/done/error 事件 | 对话 |
| conversation.* | list / create / rename / pin / delete / search | 会话管理 |
| kb.* | list / create / importDocs / rebuild / search | 知识库 |
| agent.* | run / stop / confirm / reject + 工具事件 | Agent |
| sys.clip.* | read / write | 剪贴板 |
| sys.capture.* | start / cancel | 截屏 |
| app.* | showMain / showQuick / hideQuick / quit / autostart | 窗口与应用 |

事件型通道（`chat:delta` 等）以 `msgId` 关联，渲染层按 id 合并。

## 5. 安全设计

- Key：safeStorage 加密落库（Windows 下即 DPAPI）；渲染层永远只拿 label / 状态 / 尾 4 位，不拿明文；
- 渲染层：CSP 限制脚本来源；`will-navigate` / `setWindowOpenHandler` 拦截外部跳转（转 `shell.openExternal`）；
- Agent：授权目录白名单（realpath 前缀匹配）；副作用确认卡片展示完整命令与写入路径；破坏性操作无「不再问」；命令执行加超时与输出截断；
- 单实例：`requestSingleInstanceLock`，二次启动唤起主窗口。

## 6. 工程化

- 构建：electron-vite（主进程 / preload / 渲染三段构建）；打包 electron-builder → NSIS 安装包；
- 零原生模块：SQLite 用 Node 内置 node:sqlite（Electron 45 内置 Node 24.22），向量检索为纯 JS 余弦；无 ABI 漂移风险；
- 冒烟：`MINIAGENT_SMOKE=1` 启动应用 2.5s 后自动打印 SMOKE_OK 并干净退出，用于无人值守验证；
- 质量基线（沿用既有习惯）：`npx prettier --check`、`npx eslint "src/**" "electron/**"`、`npx vitest run`；
- 主进程核心逻辑（网关调度 / RAG / Agent 循环）必须有单测，IPC 层保持薄封装；代码风格延续 apikey测试工具 惯例（electron/*.cjs 主进程、src/ 渲染层）。

## 9. v1.1 增量：本地嵌入与缺口补齐（2026-11-20）

### 9.1 知识库本地嵌入（onnxruntime-node + faiss-node + BGE 中文模型）

- **模型**：`bge-small-zh-v1.5`（512 维）/ `bge-base-zh-v1.5`（768 维）的 ONNX 导出（Xenova 仓库），每模型提供量化 int8 与非量化 fp32 两档，共 4 个模型包；建库时二选一（默认推荐 small 量化）；
- **一键下载**：设置页「本地嵌入模型」分组（默认源 `hf-mirror.com`），每包仅含 `model.onnx / model_quantized.onnx + tokenizer.json + config.json`，落 userData 下 `models/<model>-<quant>/`；下载走 `models:download` 后台执行 + `models:progress` 广播（150ms 节流），`.part` 临时文件原子改名防半截包，文件齐全性校验（model 文件 > 1MB）；
- **分词**：`rag/tokenizer-bert.js` 纯 JS WordPiece（对齐 HF BertNormalizer / BertPreTokenizer / WordPiece：CJK 逐字切分、贪婪最长匹配 + `##` 续接、[CLS]/[SEP]、512 截断），只读 tokenizer.json，不引入额外原生依赖；
- **推理**：`rag/embed-local.js` 经 onnxruntime-node（NAPI 二进制，无 ABI 重建）创建会话并按包缓存，int64 输入（input_ids/attention_mask/token_type_ids）+ CLS 池化 + L2 归一化；检索查询自动加 BGE 官方指令前缀「为这个句子生成表示以用于检索相关文章:」；
- **检索**：`rag/faiss-index.js` 用 faiss-node `IndexFlatIP`（两侧归一化后内积 = 余弦）按库缓存内存索引，导入/重建/删除文档时失效；faiss 加载失败自动回退暴力余弦（行为等价）；远程嵌入知识库同样走 faiss，保持单一检索路径；
- **数据模型**：`kbs` 迁移至 v2（`user_version` 2），新增 `embed_source`（local/remote，旧库默认 remote）与 `embed_quant`；备份导出/导入列同步兼容；
- **打包**：两原生模块进 `dependencies` 并由 externalizeDepsPlugin 外部化；electron-builder `asarUnpack` 解包 onnxruntime-node / faiss-node / bindings；
- **验证**：真实 bge-small int8 端到端 spike——query「报销要怎么走流程？」命中报销流程 chunk 0.674（无关 chunk < 0.27），faiss 与余弦一致（`scripts/spike-local-embed.js`，可复跑）。

> 设计偏差留痕：§6「零原生模块」决策按用户要求更新——RAG 嵌入/检索引入 onnxruntime-node 与 faiss-node。两者均为 NAPI 二进制（Node/Electron 通用，无需 node-gyp 重建）；faiss-node 在中国网络环境 prebuild-install 直连 GitHub release 会超时，需手动经镜像下载预编译产物放入 `node_modules/faiss-node/build/Release`（本仓库已就位；CI 环境直连正常），详见完成报告。

### 9.2 缺口补齐（对照需求文档）

- **4.2 周期自动探测**：`probe-scheduler.js` 每分钟一跳，按供应商 `probe_interval_min` 到期自动探测其全部 Key（≤0 关闭；手动探测/保存供应商后重置计时；测试模式不启动，首跳即完成启动探测）；
- **4.1 消息删除**：`chat:messageDelete` IPC + 单条消息软删（消息操作按钮 + 统一确认弹窗），`messageDeleted` 事件同步各窗口；
- **4.1 top_p**：会话设置提供「核采样」（top_p），gateway 按 policy 条件透传 payload；随机性/核采样/保留轮数另提供三档推荐值，与数值输入写同一字段；
- **文档漂移修正**：README/技术设计中 better-sqlite3、sqlite-vec、旧测试数的表述更正为实际实现。

### 9.3 采样设置改为全局（2026-11-20）

- **位置**：原聊天区右侧抽屉/停靠面板的会话设置整体移除（`ChatDetails.vue` 删除），采样参数改为「设置 → 会话」分组的全局配置，对所有会话生效；聊天页头不再有「会话设置」按钮；
- **落库与优先级**：全局采样写入设置键 `chatSampling`，gateway 与 agent 两条链路都经 `effectiveParams(全局设置, provider, model, 旧会话 contextPolicy)` 解析，优先级为「全局 `chatSampling` → 会话级 `contextPolicy`（仅旧数据兼容）→ 模型参数 → 服务端默认」；
- **移除项**：「所属项目」下拉、默认供应商与默认模型下拉（服务与模型改由用户在输入区手动选择，`resolveModel` 只读会话值与第一个启用供应商回退，不再读 `defaultProviderId`/`defaultModel`）；聊天区抽屉相关偏好（`chatDetailsOpen`/`chatDetailsPinned`）与 `ui.showDetails`/`detailsPinned` 一并删除；
- **档位推荐**：随机性（0.2 严谨 / 0.7 均衡 / 1.1 发散）、核采样（0.5 收敛 / 0.9 均衡 / 1.0 开放）、保留轮数（6 精简 / 20 标准 / 50 长程），数值输入与档位按钮写同一字段；
- **模型参数下放**：最大输出长度（`max_tokens`）与上下文上限（`maxChars`）从会话设置移入提供商模型条目，保存于 `providers.models[]`（编辑供应商 → 模型 chip 齿轮 → 模型参数，随「保存供应商」落库）；这两项只取模型参数，未配置时不发送 `max_tokens`、上下文回退 12000 字符。
