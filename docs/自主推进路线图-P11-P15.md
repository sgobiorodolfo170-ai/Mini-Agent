## 1. 目标与边界

本轮目标依次完成：

1. 完整拖拽 DAG 编辑；
2. 运行中动态新增节点；
3. 对话全文检索；
4. 端到端同步；
5. 电脑操作。

总原则：优先复用 Electron、Vue、Pinia、node:sqlite、Fastify/ws、BrowserService、审批与审计；不引入云服务、账号体系、付费组件或大型执行框架。每阶段只增加完成该阶段所需的最小依赖。

非目标：云盘式文件同步、任意网页 JS 执行、验证码绕过、自动支付、UAC 提权、锁屏/RDP 强制操作、无限制桌面坐标点击、完整多主 CRDT、默认端到端加密。

## 2. 技术选型与成本

| 能力 | 推荐方案 | 新增依赖 | 成本 | 主要复用点 |
|---|---|---|---|---|
| 拖拽 DAG | Vue Flow v2 `@xyflow/vue` 受控模式 | 1 个直接依赖；不加 Dagre/ELK | 中 | Vue、Pinia、现有 layers/依赖数据 |
| 动态节点 | 扩展现有 `graph.mutateGraph` 与 Run 队列 | 0 | 中 | DAG 校验、事务、etag、claim、失败级联 |
| 全文检索 | SQLite 内置 FTS5 `trigram` + 短词 LIKE 回退 | 0 | 低 | node:sqlite、repos、现有会话搜索 UI |
| 端到端同步 | 本地优先、局域网配对设备、单写 CDC；后续离线多写冲突副本 | 0 | 高 | 远程 TLS、设备授权、CSRF、ws、事件存储 |
| 电脑操作 | 浏览器 CDP + Windows UIA 语义助手 + 现有截图 | 0 个 npm；1 个 .NET 助手 | 高 | BrowserService、截图、工具审批、审计、急停 |

不采用零依赖自研完整 DAG：坐标变换、连线路由、命中检测、框选、缩放、键盘操作、撤销和可访问性累计成本高于一个 MIT 依赖。Vue Flow 官方当前安装包为 `@xyflow/vue`，核心组件自带拖拽、缩放、平移、连接、保存/恢复与无障碍支持。2026-11-25 核验 npm：`@xyflow/vue@2.0.3` 为 MIT，直接依赖 `@vueuse/core` 与 `@xyflow/system`，peer 要求 Vue `^3.5.27`；当前锁定 `vue@3.5.45` 已满足，无需升级 Vue。

## 3. 无人值守执行规则

每个阶段按“契约 → 数据/服务 → UI → 单测 → E2E → 文档 → 质量门禁”推进，完成后再进入下一阶段。

- 不提交、不推送 Git；保留当前工作区，不重置或覆盖用户改动。
- 不购买服务、不创建外部账号、不向公网写入业务数据。
- 数据库迁移必须可在临时副本上验证；破坏性迁移前自动备份。
- 新能力默认使用功能开关；同步和电脑操作默认关闭。
- 外部副作用必须沿用现有审批、授权目录、参数哈希、审计和急停；无人值守只执行预授权范围内动作。
- 遇到以下情况停止并记录：需要管理员/UAC、验证码、支付、系统密码、不可恢复删除、真实外部联系人/消息发送、依赖不可用、连续两轮同一测试失败。
- 每阶段固定门禁：`npm run format`、`npm run lint`、`npm test`、`npm run test:coverage`、`npm run test:e2e:mock`、`npm run build`；涉及安装包时增加 NSIS、静默安装、`SMOKE_OK` 与安装版专项 E2E。

### 范围

- 节点拖拽、画布平移/缩放、适应视图、框选、多选、键盘移动/删除。
- 拖拽创建/删除依赖连线；非法连线即时提示，服务端再次校验。
- 节点目标编辑、排队节点删除、撤销/重做、布局自动保存与恢复。
- 运行中/已完成节点只读；不通过 UI 改执行状态。

### 实现

1. 新增 `src/components/agent/TaskGraphEditor.vue` 与 nodes/edges 适配器。
2. 只添加 `@xyflow/vue`；使用 `shallowRef` 和受控 nodes/edges，不引入自动布局包。
3. 初始布局复用服务端 `layers`；用户布局按 `runId` 保存坐标，视口单独保存。
4. Schema v15 为 `run_graphs` 增加 `layout_json`、`viewport_json`、`layout_revision`。
5. 新增窄 IPC：`agent:graph:layout:get/save`。布局保存不改变执行 etag；依赖变更仍走 `agent:graph:mutate`。
6. 连接/断边操作转换成现有 update ops；服务端仍是 DAG、深度、节点数和状态的最终裁决者。
7. 提供列表式依赖编辑作为键盘与无障碍替代路径。

### 验收

- 12 节点 / 3 层图可拖拽、缩放、平移、适应视图，无控制台错误。
- 拖拽坐标和视口重启后恢复；依赖变更刷新后不丢失。
- 自环、重复边、不存在的节点、超过 12 节点/3 层、环依赖均被拒绝。
- 运行中节点不可拖动修改执行语义；排队节点 claim 后不可编辑。
- 键盘可完成节点选择、依赖编辑和删除；窄窗口无横向溢出。
- 新增画布单元测试、真实 Electron 拖拽/连线 E2E；旧任务图 E2E 不回归。

### 回滚

## 5. P12：运行中动态新增节点

### 范围

- 父图为 running、父 Run 为 running/waiting_child 时新增节点。
- 新节点可依赖已完成、运行中或排队节点；不可依赖自身，不可造成环。
- 运行中/已完成节点不可改目标或依赖；排队节点仍按 P11 规则编辑。
- 添加操作幂等，重复提交返回同一 Run。

### 实现

1. 从 `index.js` 的 Run 登记逻辑提取可复用的图节点创建服务，避免复制会话、消息、Run、权限和工作区初始化。
2. `graph.mutateGraph` 增加 `add` op：`clientId/key/goal/deps/position`；在同一事务创建会话、Run、用户/助手消息和边。
3. 新增节点继承父项目、供应商/模型、权限和 mandate；`run_spec_json`、消息关联、checkpoint 字段一次写全。
4. 复用 `validatePlan`、etag、`isClaimed`、`runQueue.schedule` 和 `graph.updated` 事件。
5. 增加 `graph_nodes.created` 审计事件；新增 Schema v16 的 `graph_node_requests` 幂等表或等价唯一约束。
6. 父图即将完成与 add 竞争时由事务和最终状态检查决定唯一结果，不允许“图已 done 但仍加入 queued 节点”。

### 验收

- 一个节点运行中时新增下游节点，依赖完成后自动启动。
- 新增节点依赖运行中节点时不会提前启动。
- 相同 `clientId` 重试只创建一个 Run；etag 冲突不产生半提交。
- 节点上限/深度/环/非法依赖/父状态/claim 竞态均有拒绝测试。
- 图全部终态后禁止新增；失败节点的下游新增遵循现有失败级联策略。
- 真实 E2E 覆盖“运行中新增 → 等待依赖 → 自动执行 → 图完成”。

### 回滚

`dynamicGraphNodesEnabled=false` 禁用 add 入口；已创建节点继续由现有队列执行，不删除数据。

## 6. P13：对话全文检索

### 范围

- 搜索会话标题、系统提示词、消息正文和工具调用文本。
- 结果定位到具体消息并高亮；区分标题命中与正文命中。
- 默认不索引附件内容、密钥、授权头和敏感 meta。

### 实现

1. Schema v17 新增 `messages_fts`：`content='messages'`、`tokenize='trigram'`，索引 `content/tool_calls`。
2. 使用 insert/update/delete 触发器维护索引；迁移时执行 `rebuild`。软删除行在查询层过滤。
3. 新增 `repos.searchMessages(db, { query, conversationId, limit, cursor })`，返回消息、会话、字段和片段。
4. 查询词始终作为绑定参数；FTS 字符串转义后构造 phrase query，不把原始用户词当 FTS 语法。
5. 少于 3 个 Unicode 字符或空索引环境回退到转义后的 LIKE；限制 100 条，游标分页。
6. 现有 `searchConversations` 保留兼容；新增 IPC `chat:searchMessages`。
7. 搜索框增加“全部对话”模式，250ms 防抖，点击结果跳转消息并高亮。

### 验收

- 中文 2/3/4 字、英文子串、大小写、标号、引号和 FTS 保留字符均有测试。
- 更新、软删除、重新生成、编辑重发后索引立即一致。
- 旧数据库迁移可重建索引；10k 消息批量导入后可接受响应。
- 查询注入字符串不改变 SQL/FTS 语义；无结果和空查询状态明确。
- UI 可跳到命中消息；远程搜索复用同一服务且保持设备权限隔离。

### 回滚

`messageSearchEnabled=false` 回到会话标题/正文 LIKE 搜索；FTS 虚拟表可保留，不影响旧查询。

## 7. P14：端到端同步

### 范围定义

首期“端到端”指两台已配对设备之间可验证、可重试、可审计的数据同步，不要求公网云服务。默认单写桌面权威端；移动端可离线暂存操作，重连后按会话租约提交。多主离线编辑后续以冲突副本实现，不伪装成 CRDT。

不同步：API Key 明文、DPAPI 密文跨设备直接复用、下载文件、模型二进制、知识库 embedding；这些对象走独立引用与按需下载。

### 阶段

**P14-A：同步基础与单写 CDC**

- Schema v18 增加 `sync_changes`、`sync_cursors`、`sync_leases`、`sync_conflicts`。
- 在仓库事务写入 outbox；直接 SQL 路径通过审计扫描补齐，保证变更与业务写入同事务。
- 每条变更含 `changeId/deviceId/entity/id/op/baseVersion/newVersion/payloadHash/createdAt`。
- 复用现有 TLS、设备绑定、短期会话、CSRF、WS 心跳、epoch/seq 和事件 ACK。
- 新增 REST：握手、拉取变更、推送变更、确认游标、冲突查询；所有写请求鉴权与审计。

**P14-B：离线与冲突**

- 会话级写租约；租约过期后允许接管，但旧写请求必须被拒绝。
- 消息追加采用 `conversationId + seq + clientId` 幂等；编辑采用版本比较。
- 冲突不静默覆盖：保存双方版本，默认保留本地并提示用户选择。
- 断线队列持久化；指数退避、乱序缓冲、重复去重、游标确认与崩溃恢复。
- FTS 索引和向量索引在本地数据落地后重建，不作为同步载荷。

**本轮安全收口**

- 项目同步只保留名称、置顶、排序和时间戳等元数据；路径与验收命令不离开本机，远端不能创建或删除本地项目。
- 会话和消息写入同时校验租约 owner、过期时间与 epoch；旧租约重放被拒绝，新会话允许 operate 角色先创建再获取租约。
- 活跃消息的 `(conversation_id, seq)` 唯一；冲突记录绑定 epoch，local/remote 解决重新校验权限，远端强制应用保留 `new_version`。

**P14-C：完整备份与可选 E2EE**

- 扩展备份表清单，纳入任务图、检查点、同步游标和冲突记录；向量 BLOB 继续单独编码。
- 如要求 E2EE，单独设计设备密钥、密钥轮换、恢复码和字段级加密；未完成前 UI 明确“已认证加密传输，非端到端内容加密”。

### 方案取舍

- 首选自研事务 outbox：与现有 repos/remote 控制力最好，零新增依赖，但不是 CRDT。
- SQLite Session changeset 可作为 P14-A 技术验证候选：Node 22.12+ / Electron 自带 Node 提供 `createSession/changeset/applyChangeset`，但 changeset 不自动清零、不跟踪虚拟表、要求主键，必须验证 Electron 实际 API 与冲突行为。
- PowerSync/Electric/cr-sqlite 暂不采用：分别引入服务端、Postgres 写链路或原生扩展/CRR 改造成本；无人值守阶段不建立外部付费依赖。

### 验收

- 两台设备离线编辑后重连，最终数据一致；重复、乱序、断电、游标回退不丢数据。
- 相同消息/操作重试幂等；冲突有双方版本和明确解决记录。
- 未授权设备无法拉取或推送；TLS/CSRF/权限矩阵回归通过。
- 同步关闭时本地功能完全可用；恢复网络后自动追赶。
- 10k 变更批量同步、WS 重连和迁移回滚有量化记录。

### 回滚

`syncEnabled=false` 停止收发但保留 outbox/游标；禁止在未确认冲突前删除同步表。

## 8. P15：电脑操作

### 范围

- 先支持 Chromium 页面与暴露 UIA 语义的 Windows 应用；自定义画布应用只做截图辅助，不承诺盲点可靠操作。
- 工具：`computer_list_windows`、`computer_snapshot`、`computer_click`、`computer_type`、`computer_key`、`computer_scroll`、`computer_capture`、`computer_stop`。
- 元素使用短期 `ref`，绑定窗口、进程、控件和快照代次；过期即拒绝。
- 默认只读；点击/输入/快捷键按副作用审批，高风险动作逐次确认。

### 实现

1. 新增主进程 `ComputerService`，所有动作经统一授权、审批、审计和急停网关。
2. 浏览器优先现有 BrowserService；需要真实输入时通过 `webContents.debugger` 调用 CDP `Input.dispatchMouseEvent/dispatchKeyEvent`，不开放远程调试端口。
3. DevTools 会 detached debugger；打开 F12、关闭标签、导航和人工接管时必须清理附件并转人工。
4. 原生应用新增 `native/computer-uia` .NET 10 Windows 助手，使用 UIAutomation COM 读取 Name/ControlType/Patterns，并执行 Invoke/Value/Selection 等语义动作。
5. 助手通过受限 JSON Lines stdin/stdout 通信，固定动词、参数白名单、超时和输出上限；不暴露任意 PowerShell/命令。
6. 截图复用 `capture.js` / `desktopCapturer`；DPI、多屏和窗口坐标归一化。
7. 增加全局急停、动作频率限制、前台窗口校验、锁屏/最小化/RDP 检测；密码控件只允许“已遮蔽”标记，不读取值。

**本轮安全收口**

- UIA 在原生动作前复核绑定窗口与前台进程；密码属性读取异常时按密码控件处理，失败关闭。
- 浏览器键盘/文本输入前检查焦点，密码或未知焦点拒绝；CDP 命令 10 秒超时并确保 detach。
- 电脑输入值、按键和浏览器 URL 查询在审批与审计前脱敏；功能关闭后急停仍可终止助手。
- 真实 E2E 覆盖记事本 ValuePattern 写入、全选/复制按键、剪贴板回读，以及安装版 UIA 窗口树和截图。

### 验收

- 真实记事本/计算器或等价 UIA 应用完成列表、快照、Invoke、Value 输入和截图。
- 真实 Chromium 页面完成点击、输入、滚动；DevTools 切换不残留 debugger。
- 元素 ref 在窗口切换/导航/超时后失效；不可操作其他 Run 的标签。
- UAC、密码框、支付、验证码、系统设置等高风险目标默认拒绝。
- 远程电脑操作必须 TLS + 设备授权 + CSRF；未授权/过期会话全部拒绝。
- 审计不记录密码、密钥、完整敏感文本；急停后进行中动作立即终止。
- .NET 助手在无开发者工具的干净 Windows 环境可运行；安装版 E2E 覆盖原生模块/进程启动。

### 回滚

`computerUseEnabled=false` 时关闭工具注册并终止助手进程；不影响浏览器、截图和本地 Agent。
