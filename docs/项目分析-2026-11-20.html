Mini Agent 项目分析

Windows 桌面个人 AI 助理(Electron 45 + Vue 3):多会话对话 · 多 Key 调度 · 划词/截屏 · 本地知识库 RAG · Agent 工具调用。本报告基于全量代码扫描、需求/设计文档与测试基线的交叉核对。

8,732源码行数(src + electron,65 文件)
243单元测试(30 文件)全绿
15+3E2E 用例(mock + 真实提供商)全绿
66.3/72.9/79.6覆盖率 语句/分支/函数 %(门槛 58/68/73)
11张 SQLite 数据表(全软删 + 同步预留)
21个 Agent 内置工具(三级风险确认)

01项目定位与现状

一句话:把「问答—查资料—干活」收敛进一个全本地的 Windows 托盘应用。

现状

  • v1.0 已交付:NSIS 安装包(dist-app/,117.8MB,未签名)完成静默安装与安装版冒烟;
  • 迭代节奏极快:2026-11-19 立项,两天内走完 v0.1→v0.9 九个修订,里程碑 M0–M5 全部关闭;
  • 质量工程完备:单测 + e2e + coverage 门槛 + eslint/prettier + GitHub Actions(windows-latest:lint→coverage→mock e2e)。

架构判断

  • 分层干净:渲染层 4 窗口沙箱化(contextIsolation/sandbox),preload 按 --bridge 暴露最小 API 面;全部网络与系统访问收敛主进程;
  • 零原生模块:node:sqlite 内置 + JS 暴力余弦检索,规避 ABI 风险,个人规模(万级块)毫秒级,决策合理且已在技术设计留痕;
  • 纯函数化测试友好:调度器/Agent 循环/守卫/切块均为依赖注入的纯函数,这是 243 个用例能稳定全绿的结构性原因。

02核心能力评估

四条主线,亮点与局限并存;局限多数已记录在完成报告 §5,属「知情取舍」而非遗漏。

对话 + 多 Key 网关(electron/main/gateway/)

  • 亮点:OpenAI 兼容协议统一接入任意中转;Key 状态机(可用/无效/冷却)完整,429 指数冷却封顶 30min,SSE 手写解析 + AbortController;vision 多模态组装、会话级模型覆盖、上下文字符预算截断都有;
  • 局限:流式建立后中断不换 Key 重试(仅请求建立阶段);Key 重试逻辑与 Agent 侧重复且次数不一致(3 vs 2,见 05)。

知识库 RAG(electron/main/rag/)

  • 亮点:pdf/docx/md/txt 全纯 JS 抽取(mammoth/pdfjs legacy),Markdown 标题树切块(800/120)、SHA1 去重、[n] 编号注入与 kbRefs 引用卡片,链路闭环且有真实 docx/pdf 样本测试;
  • 局限:暴力余弦无 ANN(自用规模可接受);图片型 PDF 无 OCR;文档变更无增量重导入;四个切块/检索参数(kbTopK 等)主进程可读但无 UI 入口。

Agent 运行时(electron/main/agent/)

  • 亮点:21 工具覆盖文件/命令/联网/浏览器/MCP/子 Agent/记忆/计划;三级风险门(只读放行/副作用确认/破坏性命令内容级正则强制逐次确认)设计成熟;每次调用落库可回放;MCP 为自实现 JSON-RPC over stdio;
  • 局限:browser_* 仅文本级交互;mcp_call_tool 每次起停进程,高频调用开销大;run_command 固定 PowerShell。

系统级快捷(electron/main/sys/ + 4 窗口)

  • 亮点:快速窗/悬浮球/托盘/全局快捷键齐备;划词用 PowerShell SendKeys + 剪贴板 diff 零依赖实现(150ms 后还原原剪贴板);截屏经 desktopCapturer 框选裁剪走 vision;
  • 局限:仅光标所在屏;管理员权限/全屏窗口可能取不到选区(文档已给「改用截屏」兜底)。

数据流(聊天):ChatView.send → chat store → IPC chat:send → gateway.sendChat 落库 streaming 占位 → resolveModel → KB 向量检索 → buildContext → scheduler.pickKey → chatStream(SSE)→ delta 广播 → chat.handleEvent 增量渲染 → done 落库带 kbRefs/warnings meta。链路单一清晰,事件契约经 e2e 验证。

04质量与测试基线

测试不是摆设——e2e 曾揪出 7 个单测不可能发现的生产级缺陷(preload 沙箱崩溃、reactive Proxy 过不了 contextBridge、Electron 45 解密包装对象等)。

单元测试 · 243 用例 / 30 文件

  • 主进程:SSE/流式客户端/调度器/探测/上下文/网关全链路(mock fetch)/仓库层/Key 加解密/守卫+风险升级/循环/28 例工具处理器/MCP 真实子进程握手;
  • RAG:切块/真实 docx+pdf 解析/嵌入/导入→检索→去重闭环;
  • 渲染层:5 个 Pinia store(jsdom)事件流状态机。

E2E · playwright-core 驱动真实应用

  • mock 套件 15 用例:会话 CRUD、流式全链路、429 换 Key、RAG 带引用、Agent 真实落盘、DPAPI 落盘 enc: 前缀;
  • real-provider 3 用例:真实中转站全链路(不进 CI);
  • 基建:本地 OpenAI 兼容 mock 服务(SSE 三模式/429 注入/确定性 embedding/坏鉴权头拦截)。

防回退机制

  • coverage thresholds 58/68/73(语句/分支/函数),当前余量 8/5/6.6 个百分点;

06风险与安全评估

安全设计(分级确认/授权白名单/DPAPI/最小 API 面)是本项目最强项;剩余风险多为「自用可接受」级别,已逐一标注缓解现状。

风险 评估与缓解现状 级别
Key 明文暴露面 safeStorage 不可用时降级 plain: base64 落盘(有格式标记);备份勾选含 Key 时导出明文 JSON(UI 已警示)。自用场景可接受,但应意识到这是设计内的明文通道 中·知情
划词改写剪贴板 模拟 Ctrl+C 后 150ms 还原用户原剪贴板,存在并发竞态窗口(期间用户复制会丢失内容)。低频操作,可接受;窗口期内可提示 中
主进程阻塞点 chat:export 同步 writeFileSync(ipc.js:187),大会话导出卡全应用;kb:import/rebuild 为 fire-and-forget,失败仅广播无重试 低-中
外部依赖脆弱点 DDG 兜底搜索依赖其 HTML 端点页面结构(改版即报错,配置 Tavily 可规避);web_fetch 为简化正文抽取;browser_* 仅文本级交互 低
Agent 误操作 授权目录默认为空 + 三级确认 + 破坏性命令正则强制逐次确认 + 全量审计落库 + 60s 超时;纵深防御完整,是同类个人工具少见的成熟度 低·已缓解

07建议路线

按「先兑现已承诺需求,再收敛质量,最后扩展」排序;P0 两项都是小改动大收益。

P0兑现需求缺口

  • 周期自动探测:需求 4.2 明确要求且 UI 已可配间隔,只差主进程一个定时调度(setInterval + 换 Key 时防抖),建议补齐或明确从需求中删除该条;
  • 修正文档漂移:README/需求文档的存储引擎与测试数改为实际(node:sqlite + 243),避免误导后续维护;
  • 消息删除:需求 4.1 列明,目前只有会话级删除;补 repos + IPC + store 约 1 个小时工作量。

P1质量收敛

  • 统一 Key 重试为单一调度模块(顺手统一 3 vs 2 的次数口径);
  • 清死代码 5 处 + 无用图标;ChatView 重复模板抽 ConversationList 组件,SettingsView 按五分组拆分;
  • 四个空转配置(kbTopK 等)补设置 UI 或删字段;chat:export 改异步流写;导入失败加手动重试按钮。

P2v1.x 扩展

  • 流式中断同 Key 重连 + 全 Key 顺序重试(完成报告 §8 首条);
  • FTS5 会话全文检索 + 会话标签;本地 embedding sidecar(断网/隐私场景);
  • 多屏截屏 + OCR 兜底划词;引用跳转定位;同步预留字段已就位,可启动端到端同步设计。
